# vLLM-SM75 v0.1.4 — vLLM 0.29.0、Firefly 与 DFlash2 修复

本地整合镜像已完成构建及AWQ DFlash2启动、API和单请求检查；下述吞吐属于PR兼容修补版本，完整CPU KV恢复及休眠/P8回归仍需单独验证。

## 主要变化

- **Firefly prefill**：为 INT4（W4A16/AWQ）提供 INT8 IMMA 加速，提升 prefill 吞吐。采用 hard-only 路径，prefill 时从 Marlin 权重布局即时反量化，不额外常驻完整 INT8 或干净 INT4 权重副本。当前 W8A8-FP8 prefill 仍走 Marlin。
- **Firefly all-reduce**：自定义 FP8 量化通信，支持 SHM、P2P 和多卡 butterfly，并对大消息分块，减少 PCIe 通信开销、改善多卡 prefill；支持2及更大的2次幂卡数。
- **Auto-sleep / deep-sleep**：将已有自动 offload、`exit` 透明冷启动 respawn 和并发唤醒加固适配至新版底座，保留空闲释放GPU资源、降低待机功耗及新请求自动唤醒。
- **`/monitor` 单文件监控看板**：直接查看吞吐、延迟、并发、KV缓存和休眠状态，无需额外部署；`VLLM_MONITOR` 控制开关，默认开启。
- **升级 vLLM 底座与完善镜像构建流程**：基于 vLLM 0.29.0 构建 `vllm-sm75:v0.1.4`，保留官方启动入口和默认界面样式；提供完整镜像构建与本地快速构建两种方式，支持挂载源码、更新适配代码及按需编译扩展。

### 兼容性修复

修复DFlash2权重加载与KV布局接口、CPU KV草稿分组识别，补充输入/采样预热和持久化编译缓存挂载。DFlash2、缓存及低功耗休眠是既有能力，不列作首次新增。

## 推荐使用

沿用 FP8 DFlash2 TP4、draft tokens=7、seq=4、batch=8192、利用率 0.92、最大长度 262144、FP8 e4m3 KV、每卡 GPU KV 3288334336 bytes、CPU KV 8 GiB、capture `[8]`。完整模型和草稿需预先可读，编译目录需可写；已有部署保留原模型路径和推理参数。

日常自动休眠推荐 `exit`，空闲 **30 分钟**；60 秒验收使用 `1`。它保留 API、退出 GPU 引擎，唤醒重新读取磁盘权重和编译缓存，**不保存运行时内存快照**。不额外保留整模型 CPU 权重备份，但仍需原 8 GiB CPU KV 预算、系统及加载内存。详见 [休眠说明](../sleep-and-cache.md)。

脚本推荐 `VLLM_FIREFLY=1`、`VLLM_FIREFLY_AR=auto`、`VLLM_ALLREDUCE_USE_FLASHINFER=0`，与本次 PR 测试路径一致。关闭 Firefly 用 `VLLM_FIREFLY=0 VLLM_FIREFLY_AR=0`；仅关闭其通信优化用 `VLLM_FIREFLY_AR=0`。`--disable-custom-all-reduce` 不会关闭 Firefly all-reduce。

## 性能与验证范围

4× Tesla T10 16 GiB、FP8 DFlash2 TP4：PR 兼容修补版本的 1–64K prefill 比已保存的 v0.1.3 基线提升 **3.8%–5.3%**；8–64K decode 差异 **+0.07%–+0.74%**，基本持平。128K 为 **978.19 tok/s prefill、166.39 tok/s decode**，没有同口径旧版 128K 基线。

旧版为三轮中位数，新版每长度一轮，512 输出 tokens，均无前缀命中；prefill 为输入 tokens/首字时间。1K/4K 输出与接受率变化，不能把 decode 波动作为普遍加速结论。详见 [完整数据与证据边界](../validation/v0.1.4.md)。

CPU offload 实际恢复、P8/透明唤醒的数据来自此前独立 0.29 候选镜像；这些修复已移入整合镜像，但实际恢复及完整休眠周期仍需回归。整合镜像已完成 AWQ 首次请求无 JIT 检查。AWQ 休眠与CPU KV恢复、MTP、CPU/reload 休眠、多用户高并发和模型质量尚未完成本轮验收。

## 更新与发布

版本升级为 v0.1.4，不改 v0.1.3 的 Release 正文、标签或附件。本次发布提供 v0.1.4 源码 zip/tar.gz 与 SHA256SUMS；它们是源码构建包，不是预构建 Docker 镜像。重建镜像和容器时保留模型及编译缓存挂载。不同代码/依赖可能合理失效，不能承诺跨版本全部缓存可复用。

## AWQ 修复、优化与实测

保留AWQ dtype/布局适配和DFlash2加载修补，合入Firefly INT4 prefill、FP8 all-reduce、CPU KV分组及首次请求预热修复；启动参数沿用AWQ独立配置。PR兼容镜像已完成1–128K测试：32K prefill/decode为1433.67/215.57 tok/s，128K为1124.88/198.40 tok/s。后续整合修复尚待整包验收，不能据此宣称CPU KV恢复或AWQ休眠已验证。
