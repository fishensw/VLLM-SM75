# vLLM-SM75 v0.1.4 — 底座升级至 vLLM 0.29.0

v0.1.4 把基础镜像从 `vllm/vllm-openai:v0.28.0-cu129` 升级到 `v0.29.0-cu129`（固定 amd64 digest `sha256:7ef5a35d1ef8ce2cf9d671dd91eec6e367c5849262e0362b4d3d4a26be0d87d2`），我方镜像名 `vllm-sm75:v0.1.4`。本仓库是 overlay 仓库（整文件覆盖底座 vLLM 包），本次把被改过的 overlay 文件适配到 0.29 的包结构。

## 用户可见变化

- 底座 vLLM 0.28.0 → 0.29.0；`vllm` 版本断言随之更新，`torch` 与 `flashinfer` 版本不变。
- 修复 `/monitor` 监控页 overlay 漏拷导致的构建失败（见下文「修复」）。
- 既有功能（firefly prefill、FireflyAllReduce、GDN flashqla_sm75、自动休眠与透明唤醒、MTP5、DFlash2）保持不变，仅跟随 0.29 的接口演进。

## 0.28 → 0.29 的兼容性结论

- **torch 仍 2.13.0、flashinfer 仍 0.6.18**（在 v0.29.0-cu129 容器内实测）。CUDA kernel 的 torch ABI 与 0.28 一致，FlashQLA / firefly 两个 `.so` 仍用底座 torch 现场编译、ABI 自动跟随，无需换 flashinfer wheel。
- **0.29 包结构对本 overlay 无破坏**：被覆盖的 14 个文件路径、firefly 新增文件的父目录在 0.29 都仍存在，`install_sm75_overlay.py` 映射表与 Dockerfile COPY 无需因 0.29 改动。

## overlay 适配（14 个文件）

以 0.29 版本为新基底，把本仓库相对 0.28 的功能改动逐一重放，既保留我们的功能、又保留 0.29 相对 0.28 的上游演进（新增方法/字段/env/签名变化）。关键跟随点：

- **Marlin FP8 hook**（`scaled_mm/marlin.py`）：0.29 把 `weight_scale_inv` 属性改成动态 `_block_scale_name(layer)`，firefly 快照改用 `getattr(layer, self._block_scale_name(layer))`；`is_supported` 去掉 0.29 已删除的 `VLLM_TEST_FORCE_FP8_MARLIN`。
- **envs**：保留 0.29 新增的全部 env、未加回 0.29 已删的 3 个（`VLLM_TRITON_ATTN_USE_TD`、`VLLM_ROCM_USE_AITER_FP4_ASM_GEMM`、`VLLM_TEST_FORCE_FP8_MARLIN`）；`VLLM_ALLREDUCE_USE_FLASHINFER` 默认跟随 0.29 改为开。本仓库自加的 `VLLM_FIREFLY*`、`VLLM_AUTO_SLEEP_*`、`VLLM_MONITOR` 等保留。
- **引擎链路**（`core.py` / `core_client.py` / `async_llm.py` / `arg_utils.py`）：跟随 0.29 新增的方法/字段（`check_admission`、`get_num_queued_tokens`、`get_num_unfinished_requests`、`max_num_queued_reqs` 等），auto-sleep respawn 的 `engine_sleeping` / `respawn_engine()` / `engine_manager.shutdown()` 跨文件对齐。
- **allreduce**（`cuda_communicator.py` / `custom_all_reduce.py`）：采纳 0.29 的 flashinfer-AR 重构与 MNNVL 守卫；firefly AR 插入点确认仍落在 `all_reduce` 活路径。
- **敏感参数脱敏**：跟随 0.29 的 `redact_sensitive_args`（去下划线）与 `***` 掩码，verify 脚本与测试同步。

## 修复

- **`/monitor` overlay 漏拷（阻塞级）**：`/monitor` 监控页功能把 `instrumentator/{metrics.py,monitor.py,dashboard.html}` 加入了 `install_sm75_overlay.py` 的覆盖清单，但 Dockerfile 漏了对应的 `COPY`，导致 overlay 安装阶段 `FileNotFoundError`、构建失败。v0.1.3 之前无此功能未暴露；本版本补齐 Dockerfile 三处 COPY。
