# vLLM-SM75 v0.1.5

基于 vLLM 0.29.0，本次新增运行中投机解码开关，默认采用 P-State 常驻省电，修复监控缓存问题，并增加可选的 ultra 版本。

本次更新：

- **运行中开关投机解码**：在 `/monitor` 查看状态并切换草稿计算，无需重启模型；关闭后草稿模型仍驻留显存。需在启动时配置草稿模型与 SM75Scheduler。
- **默认常驻 P-State**：空闲进入 P8，负载恢复高态 16，模型保持加载。自动休眠 exit 保留为可选模式，两种模式均可配置参数。
- **监控缓存修复**：修复启用监控看板导致推理编译缓存失效的问题，保留已有缓存兼容性。
- **新增 ultra 版本**：在标准版推理服务上增加 Web 管理、快速会话和工作台。

### ultra 新增功能

ultra 包含标准版推理服务，并增加以下功能：

- **一体化 Web 管理**：新增模型库、运行配置、快速会话、DSH 工作台和性能监控页面。
- **Web 登录与会话**：首次启动生成随机 token，支持局域网登录和会话恢复；修复登录闪跳和导航问题。
- **统一实时页头**：快速会话与工作台在相同位置显示运行状态、GPU 温度/功耗、核心/显存占用、P/D、KV 和命中；性能监控页不重复显示指标条。
- **模型生成参数**：显示服务默认数值，提供 Qwen3.8-27B 思考/非思考推荐，支持存在惩罚、自定义参数及恢复服务默认。

[ultra 详细说明](v0.1.5-ultra.zh-CN.md)

## 版本选择

**只需要推理 API，或已有聊天客户端/管理平台，选标准版；希望在浏览器中管理模型、直接聊天和使用工作台，选 ultra。**

| 项目 | 标准版 v0.1.5 | v0.1.5-ultra |
|---|---|---|
| 定位 | 推理服务 | 推理服务 + 一体化 Web 管理与工作台 |
| SM75 推理、FP8/AWQ、MTP/DFlash2、CPU KV | 支持 | 相同推理基座 |
| 运行中投机开关、P-State / 可选 sleep | 支持 | 支持 |
| 配置方式 | 启动脚本、环境变量和命令行参数 | Web 模型库与运行配置 |
| 监控 | 引擎 `/monitor` | 引擎监控 + 管理页实时状态 |
| Web token 登录、会话恢复 | 不包含 | 包含 |
| 快速会话、DSH 工作台 | 不包含 | 包含 |
| 默认端口 | 推理 API / monitor：8000 | 管理 / 聊天 / 工作台：1615；推理 API：8000 |
| 本地构建镜像 | `vllm-sm75:v0.1.5` | `vllm-sm75:v0.1.5-ultra` |

ultra 增加管理和交互功能，不代表推理内核更快。两版按需要选择一个部署即可；标准版不需要安装 ultra 才能提供推理 API。

## 推荐使用

现有 FP8 DFlash2 TP4 部署保持原模型路径、draft7、seq4、batch8192、GPU utilization 0.92、最大长度 262144、FP8 e4m3 KV、每卡 KV 3288334336 bytes、CPU KV 8 GiB、capture `[8]`。这是本次回归配置，不等同于启动脚本所有模式的默认值，也不是其他卡数的通用显存预算。

默认使用常驻 P-State（空闲 P8 / 负载回 16），保持模型加载，须准备匹配宿主驱动的 NVAPI 库。自动休眠 exit 保留为可选模式，选择 `POWER_MODE=sleep` 后默认空闲 30 分钟；休眠参数继续支持配置。同一 GPU 仅运行一个电源管理实例。完整命令见 [统一构建运行](../../docker/BUILD.md)、[FP8 推荐配置](../recommended-fp8-dflash2.md) 和 [休眠说明](../sleep-and-cache.md)。需要 Web 管理、快速会话和工作台时选择 [ultra](v0.1.5-ultra.zh-CN.md)，两者共用推理基座。

### 电源模式参数

ultra 配置界面默认“常驻 P-State（默认；空闲 P8 / 负载回 16）”，保留“自动休眠（exit，可选）”。已有保存的配置不强制改写。

| 常驻 P-State 参数 | 标准版环境变量 |
|---|---|
| 空闲进 P8（秒） | `PSTATE_IDLE_TIMEOUT` |
| 负载阈值（%） | `PSTATE_UTIL` |
| 确认时长（秒） | `PSTATE_CONFIRM` |
| P8 值 / 高态值 | `PSTATE_LOW` / `PSTATE_HIGH`（默认 8 / 16） |
| 轮询间隔（秒） | `PSTATE_POLL` |

切换为自动休眠时，继续配置 `AUTO_SLEEP_IDLE_TIMEOUT`（分钟）、`AUTO_SLEEP_OFFLOAD_TARGET`（默认 exit）以及适用模式的恢复/缓存参数。P-State 的秒数与 sleep 的分钟数不能混用；只启用所选电源模式，不叠加运行。

## 性能参考

以下沿用 **v0.1.4 历史实测**，不是 v0.1.5/ultra 的新实测数据。PCIe 3.0 ×8，4× Tesla T10 16 GiB，TP4，DFlash2 draft7；每项单轮、512 输出 tokens、无前缀命中，Prefill 按输入 tokens/首字时间计算。

补充参考：据群友实测反馈，PCIe 3.0 ×16 下 Prefill 极限约 **1800 tok/s**。

| 配置 | 输入 | Prefill（tok/s） | Decode（tok/s） | 首字时间（秒） |
|---|---:|---:|---:|---:|
| FP8 DFlash2 | 32K | 1205.85 | 179.12 | 27.17 |
| FP8 DFlash2 | 128K | 978.19 | 166.39 | 133.99 |
| AWQ DFlash2 | 32K | 1433.67 | 215.57 | 22.86 |
| AWQ DFlash2 | 128K | 1124.88 | 198.40 | 116.52 |

重复文本的高草稿接受率不代表日常聊天速度；FP8 与 AWQ 参数不同。完整条件见 [FP8 数据](../validation/v0.1.4.md)、[AWQ 数据](../validation/v0.1.4-awq.md)。本版回归与长上下文检查另见 [验证记录](../validation/v0.1.5.md)。

## 更新与发布

从仓库根目录运行 `bash docker/build.sh` 构建标准版；`EDITION=ultra bash docker/build.sh` 在相同标准基座上构建 ultra。完整构建使用独立构建机；已验证的隔离 Unraid 构建过程及限制见构建指南。

升级保留模型、编译缓存、API key 和原启动参数；使用独立候选标签，验收后切换，保留原镜像 ID 与挂载用于回退。启动脚本不会自动停止或删除现有容器。源码包及校验文件见 [v0.1.5 Release](https://github.com/fishensw/VLLM-SM75/releases/tag/v0.1.5)；Docker 镜像需自行构建，生产升级由部署者按上述步骤执行。
