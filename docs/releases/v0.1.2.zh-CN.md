# vLLM-SM75 v0.1.2 — SM75 投机解码适配

vLLM-SM75 v0.1.2 集成 MTP 和 DFlash2 适配，通过 CUDA Graph、GDN metadata 融合及 TP4 路径优化提升 decode 性能。

## 具体优化

- **投机解码优化**：适配 SM75 CUDA Graph，融合 GDN 状态元数据准备，减少验证和调度开销。
- **MTP 适配**：优化原生 MTP 验证路径，提供 MTP5 配置，适用于包含兼容 MTP 权重的模型。
- **DFlash2 适配**：完善 SM75 数值兼容、AWQ 数据类型及 TP4 计算与候选处理，支持 FP8 / AWQ 模型投机解码。
- **启动修复**：降低 FP8 模型加载 DFlash draft 时的显存分配压力。

## 已完成的性能验证

环境：4 × Tesla T10 16 GiB，TP4，SM75，PCIe 3.0 ×8，CUDA 12.9，vLLM-SM75 v0.1.2，PyTorch 2.13.0，FlashInfer 0.6.18。

vLLM-SM75 v0.1.2 基于上游 vLLM 0.28.0；以下为本次版本所整理适配代码的历史测试数据。

### AWQ：普通推理与 DFlash2

代码生成测试：单并发，输出 1024 tokens，关闭 thinking、无前缀缓存命中，取三轮中位数。下表长度为输入长度。

| 上下文 | 普通版 decode（tok/s） | DFlash2 decode（tok/s） | 提升 |
|---|---:|---:|---:|
| 1K | 56.22 | 103.30 | +83.8% |
| 32K | 51.85 | 78.77 | +51.9% |
| 128K | 42.49 | 66.25 | +55.9% |

### FP8：MTP5 与 DFlash2

相同权重、TP4、seq4、batch8192、每卡固定 3.0625 GiB GPU KV、8 GiB CPU KV offload、冻结代码任务 fp8-v1；单请求、每轮 1024 输出 token、temperature=0、关闭 thinking、无 prefix 命中。这组用于两种投机配置对比，与下面历史峰值组的参数和语料版本不同，不能混算。

| 上下文 | MTP5 prefill（tok/s） | MTP5 decode（tok/s） | DFlash2 prefill（tok/s） | DFlash2 decode（tok/s） |
|---|---:|---:|---:|---:|
| 1K | 1144.76 | 56.84 | 1015.57 | 82.28 |
| 32K | 1125.03 | 72.12 | 1138.64 | 80.44 |
| 128K | 908.59 | 52.76 | 932.99 | 66.88* |

MTP5 各三轮中位数；DFlash2 的 1K / 32K 各三轮，128K 仅一次（*）。结果与任务接受率相关，不能外推到所有聊天、SQL 和采样设置。MTP5 未改善长上下文 prefill。

### FP8 DFlash2 重复文本压力测试

单并发、DFlash7、输出 1024 tokens，取三次中位数；decode 不包含 prefill。

| 输入 tokens | decode（tok/s） |
|---|---:|
| 32768（32K） | **147.70** |
| 261120* | **130.96** |

使用 seq4/batch8192，压力测试接受率接近 100%，单轮最高 **151.28 tok/s**；日常使用性能随任务变化。

*261120-token 组包含两次冷请求和一次 GPU 缓存命中。完整配置、逐轮数据及计时方法见详细测试资料。

## SQL 测试

FP8 MTP5：25 道题、三轮，共 75 次评测，综合通过率 **93.33%（70/75）**。

## 性能说明

- **代码生成 / 长输出**：速度主要受投机接受率影响。
- **短问答 / 短输出**：响应时间主要受首字延迟和调度开销影响。
- **长文档 / 长上下文**：prefill 和 KV 访问耗时占比更高。
- **SQL / Agent / 工具调用 / thinking**：整体耗时还包括多轮生成和工具执行。
- **多并发 / 多模态**：请求形状和计算负载会影响优化路径及吞吐。

实际性能受硬件、模型、请求内容和配置影响，未达到测试速度属于正常现象，测试数据仅供参考。
