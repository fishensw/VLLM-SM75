# vLLM-SM75 v0.1.3 — 自动休眠与缓存修复

本次在 v0.1.3 内更新，版本号和镜像名 `vllm-sm75:v0.1.3` 不变。

## 用户可见变化

- 调整自动休眠时间不再导致编译缓存失效。
- exit 唤醒后，主模型、DFlash2 草稿模型和候选选择器可以复用匹配的持久化编译缓存。
- 启动脚本统一 `cache/<format>/vllm` 与 `cache/shared/flashinfer` 目录，模型下载缓存可独立指定；已有部署按迁移说明保留旧产物。
- 启动脚本选择 cpu/reload 时补齐所需 `--enable-sleep-mode`，并提供 checkpoint 路径与页缓存预热间隔变量。
- 休眠说明明确各模式的 RAM/磁盘要求、P8 条件、超时单位和验证范围。

既有功能保持：请求完成后开始空闲计时、默认脚本 30 分钟 exit、统一镜像普通/MTP/DFlash2 支持。原推理参数不因本次缓存修复而改变。

## 修复原理

1. `envs.compile_factors()` 原先把运行时 sleep 环境参数计入计算图缓存键，导致 1 分钟改为 30 分钟也重新编译。现排除四个 sleep 策略字段；真正影响计算图的环境参数继续校验。
2. EngineCore ready 回传的调度 block_size 会覆盖 API 客户端配置，本地 DFlash2 从启动输入 32 变为运行时 832。exit 重建误用该值，使草稿/候选选择器缓存键变化。现保存初始输入，并复制 cache config 供重建使用；前端保留实际调度值，block_size 本身仍参与缓存校验。
3. `CompilationConfig` 的 custom-op 运行时统计从哈希中排除，用户指定的 `custom_ops` 策略仍保留。该文件按基础 vLLM 0.28.0 完整文件加入 overlay，仅修改上述哈希排除项，Docker 构建和 overlay 安装清单同时更新。

## 已验证效果

最终修复镜像内构建测试 44 项、新增缓存回归测试 6 项通过。FP8 DFlash2、T10 ×4 实测三个阶段（已有缓存启动、60 秒 exit 唤醒、改 30 分钟启动）均 12 次 AOT 命中、零重新编译、三组缓存键一致。

60 秒空闲后 API 在线，四卡 P8、3 MiB/卡、9.97–15.31 W/卡；两个并发唤醒请求成功，完整耗时约 135.7 秒。主模型/草稿/候选选择器的缓存加载阶段约 3.81/0.76/0.06 秒。30 分钟配置已正式启动和推理验证，没有额外等待完整 30 分钟休眠周期。

上述结果不扩展为 CPU/reload、其他四个配置、长上下文或其他 GPU 的本轮验收。新增启动脚本变更单独做参数和挂载测试，不属于之前镜像 GPU 验证的代码范围。
