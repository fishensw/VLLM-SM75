# vLLM-SM75 v0.1.6 更新说明

基于项目 v0.1.5 公开提交 `2c5bfef81aadcd6c5a69812988fe14746543de89`，上游固定为 vLLM `0.30.0` / `ced6857afa0ea7b2e3f0846a62e1394e90f15607`。界面、构建与验证范围见 [工作台整合验收](../validation/v0.1.6-workbench-integration.md) 和下文的完整镜像验收。

## 推理兼容

通过 0.29.0 → 0.30.0 三方迁移保留 SM75 的 GDN、FP8 KV、Firefly、自动休眠、CPU KV offload、投机开关和缓存修复，并更新引擎/worker 的新增接口。Firefly 使用新版三参数权重 API，去除已删除的 `has_g_idx` 与第四个返回参数。

[issue #13](https://github.com/fishensw/VLLM-SM75/issues/13) 报告 FP8 DFlash2 接受率异常。本版吸收以下修复思路；来源 PR 未合并的内容均作为显式回移，不能表述为上游稳定性保证：

- [#51620](https://github.com/vllm-project/vllm/pull/51620)：量化 context KV 通过各层量化方法计算，避免融合路径切片原始量化权重、漏用 scale；非量化路径保留融合。保留本地 BF16 数值兼容，兼容返回 bias。
- [#53122](https://github.com/vllm-project/vllm/pull/53122)：草稿量化配置补齐模型 packed-module 映射；配置错误直接报错，不静默忽略。
- [#53376](https://github.com/vllm-project/vllm/pull/53376)：CUTLASS FP8 使用真实设备/编译能力判断，SM75 进入 Marlin fallback，保留已有 INT8 支持。

本轮在四张 T10 上定位到另一个实际问题：compressed-tensors 的 W8A16 将 tensor scale 展开为 channel scale；Humming 0.1.12 在相应 epilogue 中先把累加结果转为 FP16，再乘 scale，可在最终值本应有限时提前溢出。真实 checkpoint 的 RMSNorm 输入下，batch 1/7 分别观察到 3/23 个非有限值，Marlin 与反量化参考均为 0。

候选版在 SM75、FP16 输入/输出、tensor/channel FP8 上拒绝该 Humming 路径，使自动选择回退到 Marlin；不改其他架构、INT8、block/group 路径。这是本地实测支持的回退，不是上述 PR 的内容。[Humming 官方 epilogue 源码](https://github.com/vllm-project/humming/blob/a38bea41116c7c4c6e5f259809c618068db87129/humming/include/humming/arith/epilogue_arith.cuh#L176) 仍保留相关顺序，单纯升级包版本不能作为已验证修复。

加入内部固定编译标识 `0.1.6-1`，让升级后的内核选择与权重布局使用新的编译缓存；同一版本内调整空闲休眠计时或看板开关仍可复用缓存。

未按 issue 的初步猜测修改 Marlin exponent bias。不同 FP8 checkpoint 的量化层范围不同；算子通过不等同于该 issue 的同权重接受率问题已解决。

## Ultra 修复

- **统一界面与字号**：共用主侧栏和单行公共顶栏，设置使用六个横向页签；全局字号覆盖工作台、Watcher、监控和模型测试，连续调整按顺序保存。
- **原生入口恢复**：使用统计和插件按固定面板标识切换；原生组件挂载后才报告就绪，切换失败保留原页面并提示原因。
- **配置初始化恢复**：记录失败阶段与写锁超时，锁释放后限频重试，避免必须重启工作台才能恢复；不自动清理其他进程的写锁。
- **设置监听修复**：只监听目标配置及必需父目录，避免无关的受保护备份使配置监听失败。
- **切页布局稳定**：各页面使用一致的顶栏空间预算，点击工作台不再临时把运行配置框搬到侧栏并推移导航。

回收本地 v0.1.5 Ultra 中的账户登录、客户端网段策略、图片附件/视觉能力传递、用量和投机状态显示修复。主侧栏平级提供快速会话、工作台、模型库、运行配置、性能监控、模型测试、使用统计、插件和设置。设置使用横向六页签：外观显示、助手工具、模型连接、参数模板、部署硬件、账号访问。使用统计由 Watcher 原生 Insights 提供，切换页面保留已加载视图；旧控制台独立统计页已移除。DSH 原生组件通过 portal 挂载到同一 DOM 的侧栏、公共顶栏和内容区域。移除旧 monitor 覆盖，避免覆盖标准版的新逻辑；`VLLM_MONITOR=0` 仅隐藏 HTML，不禁用鉴权后的投机控制 API。

Harness 固定升级到官方 [dsh-v0.1.7-alpha.2](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-alpha.2)（预发布），统一其 267 个原生包；Node 22.23.2 与 pnpm 11.7.0 一并固定。移除六组旧版前端 bundle 覆盖，改用新版公开插件接口；管理端口根地址始终保留现有 SM75 主界面，DSH 功能嵌入工作台内容区；适配同源静态资源/RPC/WebSocket、一次性配置迁移与 V4 工具日志。原生模型设置保留可编辑和持久化，工作台只维护本地 provider。首方加载器仅在管理会话有效、同源 `/harness-ui/` 引导文档校验通过后，使用官方 `transport.ownsHost` 接口启用原生设置持久化；拒绝未知 transport、跨源地址和重定向。该声明只决定客户端设置模式，HTTP、RPC 和 WebSocket 仍逐请求执行管理台认证与来源校验。

智能体默认使用简体中文回复，新增原生 `list_directory` 用于列出当前会话工作区的文件、目录和空目录，支持分页并拒绝越界路径及外指链接。此工具不依赖命令行沙盒；命令工具报告缺少安全沙盒时，会中文说明限制并继续使用可用的原生文件工具，不扩大权限、不将命令执行标记为成功。

Harness 依赖升级的历史记录见 [Harness 升级验证](../validation/v0.1.6-harness.md)，最终界面以 [工作台整合验收](../validation/v0.1.6-workbench-integration.md) 与 [统一 UI 结构化结果](../validation/v0.1.6-unified-ui-results.json) 为准。本轮 Harness 更新不改变此前推理与 GPU 验证边界。

## 长上下文配置

新增 YaRN 1M、每卡 GPU KV 容量和 CPU KV 总容量的独立配置区域。按实际模型原生长度生成正确的文字模型覆盖，保留模型专用位置编码字段；组合向导不再覆盖这些设置。CPU KV 仍是前缀缓存层，不能增加单请求可用的 GPU 注意力容量。界面及模型配置逻辑见 [配置与验证](../validation/v0.1.6-context.md)；实际可用长度取决于 GPU KV 容量，配置值不代表已验证的推理长度。

## LMCache 分层缓存

新增可选 LMCache MP CPU＋磁盘层，固定 0.5.5 cu129 与 packed4D 布局修复。实际复现了原版恢复后乱码的问题，因此安装与启动都校验补丁；来源 [PR #4731](https://github.com/LMCache/LMCache/pull/4731) 尚未合并，不作为上游稳定性保证。

控制台可分别设置共享 CPU GiB、chunk、磁盘目录与剩余空间门槛，管理独立缓存进程并隔离不同模型/布局的数据。保持与原生 CPU KV、投机解码和显存休眠互斥；磁盘层不提供硬配额，CPU/磁盘容量不增加活动请求的 GPU KV 上限。

详见 [使用说明](../lmcache.md) 与 [本轮验收记录](../validation/v0.1.6-lmcache.md)。默认不安装本项目固定的 cu129 扩展、不启用。上游基座可能自带未适配的同名包，不能据此省略扩展安装；LMCache 的验收不改变 DFlash 与活动 GPU KV 容量的验证边界。

## 推荐入口

主 README 按简介、更新、标准版与 Ultra 对比、性能、快速构建五部分组织；[配置模板](../configuration-v0.1.6.md) 包含基本推理、正式 DFlash2 对照、长上下文、YaRN、LMCache 和 P-State。标准启动脚本新增 `MAX_MODEL_LEN`、`MAX_NUM_SEQS`、`MAX_NUM_BATCHED_TOKENS`、`GPU_MEMORY_UTILIZATION`、`GPU_KV_BYTES`、`CPU_KV_GIB`、`HF_OVERRIDES` 和 `VLLM_MARLIN_USE_ATOMIC_ADD`；CPU KV 为 0 时关闭原生连接器。Marlin 归约开关默认 0，正式参数对照模板显式使用 1，切换后需重新比较输出和性能。统一 Ultra 构建入口支持 `INSTALL_LMCACHE=1`。增量 Harness 安装需要网络，不再错误宣称 npm ci 可离线完成。

P-State 和自动休眠使用不同单位：前者空闲/确认时间为秒，后者空闲时间为分钟。高态值 16 表示恢复驱动控制；P-State 保留显存，sleep/exit 可释放显存。Ultra 的电源配置按 profile 持久化，升级保留既有值。

## 本轮完整镜像验收

基于完整官方 0.30.0 基座重新构建标准版和 Ultra，参照既有正式 Ultra 的四 T10、Qwen3.8-27B-FP8、DFlash2 draft7 参数，使用独立数据和缓存测试 prefill/decode、草稿接受率及最大实际上下文。结果以 [完整镜像报告](../validation/v0.1.6-full-images.md) 为准。旧 wheel-overlay 测试、历史性能和新的完整镜像结果分别保留来源，不能互相替代。

本轮已核对完整镜像的构建、GPU 功能、DFlash 长请求质量与性能、上下文边界、Ultra 面板和电源切换。标准版与 Ultra 完整镜像已构建并通过四卡运行时预检，DFlash2 九项性能采样各自完成；标准版 128K 吞吐和跨镜像输出等价门禁未全部通过，两版 DFlash2 的 256K 边界、Ultra 面板、自动 P-State 和 LMCache 八项回读通过。具体条件及限制见完整报告。尚未通过的项目继续列为发布限制；本地镜像和模板切换不等于公开发布。
