# v0.1.6：YaRN 与 KV 缓存配置

本文说明 YaRN 与 GPU/CPU KV 的配置方式。实际可用长度由模型和 GPU KV 预算决定。

## 使用入口

运行配置 → 编辑 → **上下文与 GPU KV**，设置上下文长度、YaRN 和每卡 GPU KV；原生 CPU KV 位于 **CPU KV 与分层缓存 → 缓存方案 → 默认**。选择 LMCache 时显示其分层缓存配置。所有改动统一保存配置，在模型下次启动时生效；不会自动重启当前模型。

- **最大上下文长度**：输入＋输出的总 token 上限或 `auto`，支持 vLLM 的十进制 `1m`（1,000,000）及二进制 `1M`（1,048,576）。快捷按钮明确使用 1,048,576 tokens；启用 YaRN 后仍可把请求上限设为 auto，让引擎按实际 GPU 容量确定运行长度，不会将 auto 强制改成 1M。
- **YaRN 上下文扩展**：读取模型 `config.json` 的文字模型信息，按原生位置长度计算倍率。例如 262,144 → 1,048,576 为 4 倍；未知原生长度必须手动填写，分层 RoPE 保留高级配置，不由通用向导覆盖。
- **每张 GPU 的 KV 容量**：GiB，可输入小数；留空恢复自动分配。显式设置 `--kv-cache-memory-bytes` 后，GPU KV 分配不再由显存利用比例决定。
- **CPU KV 前缀缓存**：原生 `OffloadingConnector` / `CPUOffloadingSpec`；GiB 是 TP 所有 rank 的总配额，支持小数。关闭会移除相应配置，陌生连接器默认保持原样。

独立配置支持未失焦直接保存、个人模板、导出/导入和高级参数回显。组合向导只设置卡数、并发、KV 精度及加速方式，不再用固定显存阈值覆盖上下文，也不重写用户的 GPU / CPU KV 配额。换用不同模型时会移除旧模型的显式 RoPE 与位置长度覆盖并重新核对新模型长度，避免把旧模型的原生长度、mRoPE 或 theta 带入新模型。

## 1M 的实现及限制

本版固定 vLLM 0.30.0。在此版本中，YaRN 的 `max_position_embeddings` 被视为已经扩展，不会再自动乘以倍率。仅写 `rope_parameters.factor=4` 再设置 1M，会因原始模型长度不足而被拒绝。

向导同时设置目标 `--max-model-len`、文字模型的 `max_position_embeddings`，以及 `rope_parameters` 中的 `rope_type=yarn`、`factor`、`original_max_position_embeddings`。对 Qwen3.8 等复合配置写入 `--hf-overrides` 的 `text_config` 内，保留 mRoPE、theta、partial rotary、其他模型配置及高级参数。没有设置 `VLLM_ALLOW_LONG_MAX_MODEL_LEN=1`，也没有绕过 GPU 缓存容量检查。关闭新增 YaRN 覆盖时恢复模型的原生设置，保留用户其他 RoPE 覆盖；若当前请求上限超过恢复后的原生上限，会一并回落到原生上限。

YaRN 调整位置编码与模型允许的长度，不会减少每 token 的 KV 存储量，也不保证扩展后的模型质量。CPU KV 卸载提供较大的前缀缓存复用层；命中后先搬回 GPU，再参与注意力计算。它不是单个请求可以直接寻址的额外 GPU KV 容量，**不能把 CPU 与 GPU 内存相加来计算可运行上下文**。减小 GPU KV 配额可节省显存，但可能降低活动请求容量、触发重算/抢占，或使目标长度无法启动。

公开 Qwen3.8-27B 配置的 16 个全注意力层、TP4、FP8 KV 条件下，单卡仅全注意力 KV 的 1M 原始下界就是 8 GiB；还需要保留 null block，并考虑 GDN、混合布局、草稿与其他开销。该数字用于说明容量限制，不是部署预算或已通过的 1M GPU 推理结果。

投机草稿使用自己的 RoPE 和上下文配置。主模型的 `hf_overrides` 不会自动传给 DFlash；当前 runner 也不能据此保证越界时自动跳过。超过草稿上限的长请求应先关闭 DFlash/MTP，或使用单独验证过的长上下文草稿。本次不自动复制主模型 mRoPE 到不同架构的草稿，也不修改已有草稿参数。
