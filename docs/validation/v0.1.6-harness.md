# v0.1.6：DeepSeek Harness 追加适配

本记录针对 Ultra 的 Harness 更新。固定官方 [dsh-v0.1.7-alpha.2](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-alpha.2)，提交 `00102833dfaee1da9f48a3a8eae9d34005a75218`；这是预发布版本，v0.1.6 继续保留未发布候选状态。

## 适配内容

- 从根包 0.1.5-rc.1 / 传递依赖 0.1.5-rc.2 混合状态升级为 267 个原生 DSH 包全部精确 0.1.7-alpha.2。完整锁包含 586 项，使用官方 npm registry 和 integrity；`npm ci`、依赖树、CLI、清单校验通过。自定义插件保留自己的版本号。
- Node 固定 22.23.2 的 amd64 镜像 digest，满足新 `undici` 的最低要求；加入上游使用的 pnpm 11.7.0，提供原生插件管理所需入口。没有通过降级依赖绕开要求。
- 停用并删除六组旧版前端 bundle。品牌、工作台状态、主题字号与统计走新版插件接口；固定版本适配器保留上游服务、状态与子插槽归属，通过原生 portal 将可视组件装配到 SM75 主界面。产品标题、字号范围与服务端采样补丁使用精确版本及唯一锚点检查。
- 管理端口根地址始终提供现有 SM75 主界面，DSH 原生内容通过 portal 装配到同一 DOM。主侧栏平级提供快速会话、工作台、模型库、运行配置、性能监控、模型测试、使用统计、插件和设置。设置使用横向六页签：外观显示、助手工具、模型连接、参数模板、部署硬件、账号访问。旧 `/dsh/` 兼容返回根地址；资源、RPC 和 WebSocket 继续由管理会话完成原生认证，浏览器不接收原生登录 token。
- 首方加载器仅在管理会话有效、同源 `/harness-ui/` 引导文档校验通过后，使用官方 `transport.ownsHost` 接口启用原生设置持久化；拒绝未知 transport、跨源地址和重定向。该声明只决定客户端设置模式，HTTP、RPC 和 WebSocket 仍逐请求执行管理台认证与来源校验。
- 已有 `settings.yaml` 经普通文件、属主与 NOFOLLOW 检查后交上游一次性导入；不在每次启动时重建它。通过原生设置服务只维护本地 provider 和默认模型，保留其他 provider 与原生 Models 编辑。迁移前后使用相同本地值，清除旧推理强度以防并行导入回滚。
- 首次工作目录显式使用 `/dsh/workspace`，不依赖精简容器缺少的桌面 XDG 工具；已有工作区由原生注册表保留。
- 默认使用简体中文回复。新增 `list_directory` 原生目录工具，使用 Harness 文件系统的规范化与包含关系检查，列出当前会话工作区的直属文件和目录（含空目录），支持分页；拒绝越界路径和外指链接。命令沙盒缺失仍保持拒绝执行并中文说明，可继续使用原生文件工具，不能据此宣称命令执行功能已恢复。
- Watcher 原生 Insights 接管使用统计，通过主侧栏“使用统计”打开，切换页面保留已加载视图，替换旧独立统计页；Watcher 同时识别 V3 wrapper 和 V4 `role:tool`，修复工具失败计数/重复错误指纹，修复原生事件顺序导致当前轮次模型显示 unknown 的问题，投影 stateVersion 升到 3 以重建旧缓存；不保存 prompt、工具参数或结果正文。客户端改用新版 `useSessionStatus`，修正四个图标导出，验证实际组件渲染和详情展开；大面板使用新版不透明弹层背景，兼容浅色/深色。
- 采样补丁以标准 file URL 引用本地模块，兼容 Linux、Windows 盘符/UNC 及含空格、中文、井号的路径；重复安装会规范早期候选的旧引用，测试实际加载模块并执行合成采样调用。
- 候选构建重新安装锁定 Harness，清除旧 node_modules，并包含共享看板模板；不会只替换 console 后继续运行旧 Harness。

## Harness 初次升级的历史检查

以下结果对应初次依赖升级时的源码和界面。当前主侧栏、设置页签、公共顶栏及 LAN 持久化适配另见 [工作台整合验收](v0.1.6-workbench-integration.md) 与 [统一 UI 结构化结果](v0.1.6-unified-ui-results.json)，不沿用旧界面的尺寸结论。

独立 Linux 容器无 GPU、无发布端口、6 GiB 内存及 2 CPU；只同步源码和合成测试数据。没有挂载真实账户、会话、密钥或模型。

|---|---|
| Linux Node 22.23.2 控制台完整回归 | 95/95，通过，0 跳过 |
| Windows 控制台完整回归 | 93 通过，2 个 Linux 专属测试跳过 |
| V3/V4 Watcher 与完整客户端组件回归 | 10 + 4 项，通过 |

| 真实 DSH 进程 | UID/GID 1000、有效 capabilities 为零、管理凭据隔离、原生 HTTP 登录与关闭、配置符号链接拒绝通过 |

Linux 回归使用 Python 3.11.2/Pillow 9.4.0，Windows 图片测试显式选择安装了 Pillow 的 Python。Windows 不具备完整 vLLM/PyTorch 环境，整目录收集依赖 Linux/GPU 的测试不适用；上表 CPU 套件是明确选出的独立测试，不能替代 GPU 测试。

真实 Chromium 浏览器验收 12/12 通过，JavaScript 异常为 0：旧 24px/浅色设置迁移、原生 Models 新增 provider 的实际字段保存、重启后同一页面恢复、工作目录不变、WebSocket 新连接实际收帧、合成流式对话、Watcher 模型标签和浅色/深色背景、V4 日志与内嵌统计均通过。采样参数检查绑定唯一用户消息，确认主对话请求携带 temperature=0.37、top_k=17、max_tokens=128 和 26 项工具定义，避免把后台标题请求误判成主对话。统计显示本次合成请求 20 tokens。

浏览器记录的 6 条 console 信息为预期的 5 次重启握手关闭和 1 次硬件端点 HTTP 400；后者的实际原因为测试容器未安装 pynvml，不计为硬件功能通过。每个 JavaScript 异常都会使验收失败，不因重启而忽略。浅色、深色截图已人工检查，Watcher 面板背景 alpha/opacity 均为 1，模型显示 audit-model，无底层文字穿透。详细断言和请求证据见 [浏览器记录](v0.1.6-harness-browser.json)。

## 复测入口

在装好固定 Harness、复制完整 `ultra/source` 并安装插件的独立测试容器中：

```bash
cd /opt/sm75-workbench/console
SM75_PYTHON=/usr/bin/python3 node --test --test-concurrency=1 --test-timeout=30000 test/*.test.mjs
SM75_DISPOSABLE_AUDIT=1 node /work/verify-harness-identity.mjs
SM75_DISPOSABLE_AUDIT=1 node /work/verify-harness-browser.mjs
```

浏览器工具还需独立测试目录中的 Playwright 1.63.0/Chromium 153；这些依赖不进入运行镜像。身份与浏览器脚本只应用于一次性环境，会创建/保留合成工作目录；不要对生产目录执行。Ultra 候选构建上下文由 `tools/package-ultra-candidate.py` 生成，依赖清单可用 `node ultra/harness/update-dependencies.mjs --check` 核对。

## 验证边界

本轮只更新 Harness 与控制台，没有修改已验证的推理覆盖。四张 T10、FP8/DFlash/CPU KV 的结果和未通过项仍以 [v0.1.6 推理验证](v0.1.6.md) 为准。浏览器模型调用使用合成 OpenAI SSE 服务，不代表新 Harness 与 GPU 模型端到端性能或工具正确率。

本记录对应的初次 Harness 升级阶段未重新构建完整官方 vLLM 基座或 Ultra 镜像，未做生产替换或公开发布。上游 alpha 的所有桌面工具、第三方插件、表格/PDF/远程 registry 行为不属于本轮完整验收范围。若自行配置旧 spill-policy `maxInlineBytes`，应按 token 预算重新选择 `maxInlineTokens`，不能直接沿用字节数。
